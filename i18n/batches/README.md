# Gemini Batch API ジョブ台帳

ローカルの `docs:ja:translate` が送信したジョブのID、翻訳対象のスナップショット、
翻訳条件と取得済み結果を `<UUID>.json` に保存します。APIキーは保存しません。
`.json` と一時ファイルは通常のGitコミットから除外しています。

CIではこのディレクトリを専用ブランチ **`translation-batch-state`** に保存します。
デフォルトブランチや翻訳PRとは独立しているため、未完了ジョブのPRをマージする必要はありません。
台帳は次の実行で復元され、同じジョブへ問い合わせます。このブランチは削除しないでください。

- `pending`：Google側で処理中。再送せず `docs:ja:collect` で確認。
- `complete`：取得完了。正常なリクエストだけを翻訳JSONへ反映。
- `failed`：ジョブ失敗・期限切れ、または明確に拒否された送信。
- `submitting` / `uncertain`：送信結果が不明。自動再送はしません。

`uncertain` かつ `name` がない場合は、Google側のバッチ一覧で表示名
`trilium-ja-<UUID>` を確認してください。作成済みなら台帳の `name` に `batches/...` を設定し、
`phase` を `pending` にして保存してから取得を再開します。
未作成と確認できた場合だけ `phase: "failed"` に変更して再送できます。
CIの場合は `translation-batch-state` ブランチ上の台帳を修正してください。
ジョブ作成は冪等ではないため、不明な状態の台帳を削除して再実行しないでください。

完了結果は再適用可能です。原文ハッシュ・見出し文脈・モデル・プロンプト・用語集が一致する
現在の翻訳単位だけに適用し、人手修正は上書きしません。
複数のCI実行で同じ結果を読み込んでも、APIへ再送したり使用量を重複記録したりしません。

台帳の`requests[].error`は個別失敗を表します。正常結果は保存済みのまま、次の手動翻訳で
未完了単位を送れます。CIの定期取得は失敗単位の再送も行いません。
